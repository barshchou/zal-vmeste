# Supabase — синхронизация дневника тренировок

Записи подходов будут храниться в облаке и подтягиваться на телефон и ПК. Без входа всё работает как раньше — только `localStorage` на устройстве.

## 1. Создайте проект Supabase

1. Зайдите на [supabase.com](https://supabase.com) **личным** аккаунтом (не рабочим).
2. **New project** → имя, например `zal-vmeste`, пароль к базе (сохраните), регион ближе к вам.
3. Дождитесь, пока проект создастся (~1–2 мин).

## 2. Выполните SQL-схему

1. В проекте: **SQL Editor** → **New query**.
2. Скопируйте весь файл [`supabase/schema.sql`](supabase/schema.sql) и нажмите **Run**.
3. Должно быть без ошибок. Таблицы: `workout_sessions`, `user_prefs`.

## 3. Создайте пользователя для пары

Один общий логин на двоих — проще всего.

1. **Authentication** → **Users** → **Add user** → **Create new user**.
2. Email и пароль — любые ваши (например `zal-vmeste@ваш-почта.com`).
3. Включите **Auto Confirm User** (чтобы не подтверждать email).

Опционально: **Authentication** → **Providers** → **Email** → отключите **Confirm email**, если письма не приходят.

## 4. Скопируйте ключи API

1. **Project Settings** → **API**.
2. Скопируйте:
   - **Project URL** → `supabaseUrl`
   - **anon public** key → `supabaseAnonKey`  
   (это не секретный service_role key)

3. Откройте [`js/config.js`](js/config.js) и вставьте значения:

```javascript
window.ZAL_CONFIG = {
  supabaseUrl: "https://xxxxx.supabase.co",
  supabaseAnonKey: "eyJhbG..."
};
```

`config.js` в `.gitignore` — в репозиторий можно коммитить только `config.example.js`, а ключи держать локально.  
Если сайт на GitHub Pages: либо добавьте `config.js` при деплое вручную, либо закоммитьте только anon key (это нормально при включённом RLS и входе по паролю).

## 5. Задеплойте сайт

Запушьте изменения на GitHub Pages как обычно. Убедитесь, что на сервере есть актуальный `js/config.js` с ключами.

## 6. Первый вход в зале

1. Откройте `him.html` или `her.html` на телефоне.
2. В блоке **Синхронизация** введите email и пароль из шага 3 → **Войти**.
3. Нажмите **Загрузить из облака** при первом входе на новом устройстве.
4. Дальше записи сохраняются автоматически (с небольшой задержкой ~0,7 с после ввода).

Кнопка **Выйти** — только на этом устройстве; данные в облаке остаются.

## Безопасность

- В базе включён **Row Level Security**: каждый видит только свои строки после входа.
- Пароль **не** храните в коде сайта — только вводите в форме входа.
- Anon key в клиенте — нормальная практика; без вашего пароля чужой не прочитает дневник.

## Лимиты бесплатного тарифа

Supabase Free: достаточно для двух человек и двух тренировок в неделю (тысячи записей). При превышении лимитов Supabase пришлёт письмо — для вашего объёма это маловероятно.

## Если не работает

| Симптом | Что проверить |
|--------|----------------|
| «Добавьте ключи в config.js» | Заполнены `supabaseUrl` и `supabaseAnonKey` |
| Invalid login credentials | Email/пароль в Supabase → Users |
| RLS / permission denied | SQL из `schema.sql` выполнен полностью |
| Не синхронится между телефонами | На обоих устройствах выполнен вход тем же пользователем |
